## Bugfixes

- Fixed a bug where, once this browser's local storage filled up, saving anything to a party silently stopped working — adding a Pokémon or editing its stats appeared to do nothing (the dialog wouldn't close), and nothing survived a reload. Storage most often fills because the cached PokéAPI data (species and per-generation lists especially) has no size limit and, on an installed app, can use up the whole allowance on its own. Saving your roster now frees that cache automatically and retries, and if it still can't save, a banner tells you instead of failing silently.
- "Clear cache" on the Storage page now also clears the cached PokéAPI lookups, not just the app files and sprite images — matching what that screen already said it did. This is what frees the space when saving is blocked.

## Technical improvements

- `Store#_save()` wraps the `localStorage` write: on failure it calls an injected `relieveStoragePressure` (wired to `PokeApiClient#evictLocalCache` in `services.js`) and retries once, then — if still failing — keeps the in-memory state usable, flips `store.saveHealthy`, and fires `save-error` / `save-ok` on each transition.
- New `PokeApiClient#evictLocalCache()` / `MemoCache#clearStored(prefixes)` drop the client's entire `localStorage`-backed cache (species list, per-Pokémon data, per-generation lists, evolution chains) and its in-memory tier. Wired into both the save-failure path and the Storage page's "Clear cache" button.
- `lib/shell.js` shows a persistent "Storage is full — your recent changes aren't being saved" banner (`#storage-warning` in `index.html`) whenever `store.saveHealthy` is false.
- Added the `length` / `key()` enumeration half of the Web Storage API to the test `localStorage` polyfill.
- Added regression coverage for the retry, the `save-error` / `save-ok` transitions, and `evictLocalCache`.
