## What changed

Effortdex now stores your data in **IndexedDB** instead of packing everything into the browser's small `localStorage` box.

- **Your roster no longer competes with the PokéAPI cache for space.** On an installed app the cached species data could fill the whole ~5 MB `localStorage` allowance and quietly block saves (the bug behind the last few patch releases). Roster and cache now live in separate stores with far more room.
- **A bad or partial write can't take out unrelated data.** Adding a battle or a Pokémon is a single small transaction; if it fails it rolls back on its own and leaves everything else intact — instead of the whole save being rewritten every time.
- **Your existing data migrates automatically on first launch.** It's imported into the new store and the old `localStorage` copy is kept as a backup, so nothing is lost and there's a way back if anything looks wrong.
- **"Clear cache" and its size figure** now also cover the PokéAPI/Smogon response cache in its new home, and that cache is capped so it can't grow without limit.

No visible change to how the app works — same parties, roster, history, and Transfer links.

## Technical improvements

- New `lib/db/` owns IndexedDB: an explicit schema (`schema.js` — `DB_VERSION` + a frozen `MIGRATIONS` chain, guarded by `test/db-schema.test.js`) and a small promise `Db` wrapper with a synchronous-`fn` transaction contract, `versionchange`/`blocked` handling, and typed errors. Nothing else in the app names an object store.
- `MemoCache` takes an injected `CacheBackend`; `services.js` wires an `IdbCacheBackend` over the `apiCache` store (falling back to the localStorage backend where IndexedDB is unavailable). `dropLegacyLocalStorageCache()` removes the old `effortdex:*` cache keys once; `trimApiCache()` enforces a per-kind entry cap on an idle sweep.
- The roster maps to relational `parties` / `rosterEntries` / `events` / `meta` rows (`lib/db/roster-io.js`). `Store#init()` (awaited before first render) imports the `localStorage` blob once and then reads from the rows; the blob stays as a dual-write backup, reconciled against the rows by a monotonic `rev` counter so a fire-and-forget mirror that loses a race can't win over the real state.
- Event append/delete (`_append` / `deleteHistoryEntry` — the large majority of writes) persist as a single targeted `events.add` / `events.delete`; structural mutations still rewrite the whole roster.
- The Gen I/II Stat-Exp backfill moved out of `Store`'s synchronous constructor into `init()`, where it runs against a warmed cache and the loaded roster.
- Added `fake-indexeddb` (dev only) and full coverage: schema/migration guards, the `Db` wrapper, the cache backend, the roster round-trip against every migration fixture (pre-event-sourcing, schema 1, schema 2, malformed shapes, slug collisions), the `Store#init()` integration, `rev` reconciliation, and the targeted-write path. 348 unit + 119 e2e tests.
- ADR 0025 records the design; ADRs 0001 / 0006 / 0009 / 0010 / 0012 / 0015 updated to point at it.

The `localStorage` blob is retained as a backup in this release; a later minor removes it.
