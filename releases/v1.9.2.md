## Bugfixes

- Fixed a bug where a saved party with any slightly off-shape data (a party or Pokémon missing part of its structure) could be wiped on load, taking every other party with it. The loader now always keeps existing parties and repairs what it can instead of falling back to an empty state.
- Stopped every app load from needlessly re-running the storage migration and overwriting the pre-migration backup, so the backup once again holds a genuine copy of your data from before the last breaking change.

## Technical improvements

- `Store#_load()` now guarantees it never swaps a real save for a fresh empty state when any parties are present — a migration that can't run, an unrecognized shape, or an outright error all fall back to loading the raw save for normalization rather than discarding it.
- `_readSchemaVersion()` now takes the stored schema number at face value (with the pre-ADR-0009 bare `schema: 2` still mapped to version 1), so a current save is recognized as current and skips the migration path entirely.
- `migrateTo2()` and `_normalizeEntries()` tolerate a party or roster entry with a missing `pokemon` / `events` array instead of throwing.
- `projectEntry()` skips a single event with an unknown kind rather than aborting the whole roster projection.
- Added regression coverage for all of the above.
